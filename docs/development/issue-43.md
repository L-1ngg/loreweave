# Issue #43: independent MCP questions

question_answer is the fifth public TanStack MCP tool. Each invocation commits a
new token-authorized run, independent thread, captured QA role, current scope and
selected version bindings. It calls shared QA directly, using the four reading
definitions, budgets and run reference validation. It never creates or borrows a
Web conversation/caller transcript and is absent from the internal Agent tools.

The schema-valid result returns answer/clarification/evidence_gap/incomplete or
explicit terminal failure, usage and immutable page resource references. Token
access is rechecked on service/model boundaries and before returning results.
MCP protocol cancellation propagates its supported abortSignal to owned execution;
the Web observer/replay contract is not exposed as an MCP background-job product.

Ran: production build/typecheck and three official-client/Playwright tests with
real PostgreSQL. Exactly five tools were discovered, both legacy session and
modern auto negotiation remained usable, and selected mixed 20/21-page, separate
single-document, library, clarification, evidence gap and incomplete questions
returned their intended schemas. Runs, budgets and page references were distinct;
source resources resolved exact versions. Invented references failed with no final
answer, empty scope/forged transcript rejected, revoked credentials denied. No Web
conversation was created and all QA requests targeted qa-fixture with exactly four
internal primitives. All passed.

Not run: real-model QA/semantic citation support and external Agent UX. Protocol
success is separate from #47's measured real-provider quality. No commit/push made.
