# Issue #41: discovery, mixed scope and follow-ups

Every new run resolves current eligibility. Explicit selection is a nonempty
server-enforced allowlist pinned at acceptance; library mode discovers paginated
current metadata and binds a document on its first substantive read. Discovered
candidates do not change future conversation scope. Current reads select the
effective index exactly. Original page reuse checks scope/version/authorization
and creates new run references; no PDF parsing is involved in normal reads.

The shared prompt distinguishes intent history from factual evidence and asks for
clarification, evidence gaps and incomplete bounded coverage. Budget guards count
the dispatch boundary and retain explicit reasons including failed attempts. The
maintained loop reaches the guard before exceeding its independent iteration cap.

and 21-page original were compared in one selected run: only the 21-page original
required a tree, and both produced current-run page references. A follow-up received
canonical history containing a deliberately unsupported prior assistant assertion,
re-read both originals and issued distinct references. Reload kept selection.
Metadata cursor enumeration, shared page reads, empty/forged selections, ambiguous
library clarification, clear filtered discovery, evidence_gap, unmatched incomplete
discovery and exact one-call exhaustion all passed. Fixture tool results are confined
to the latest user turn to prevent old-reference reuse from faking a pass.
